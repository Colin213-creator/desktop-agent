# 桌面智能体 · 架构说明

## 1. 五层结构

```
┌─────────────── 感知 perception ───────────────┐
│ screen.py   截图、活动窗口、光标、DPI 换算      │
│ uitree.py   UIAutomation 控件树定位            │
└───────────────────────────────────────────────┘
                    ↓
┌─────────────── 决策 core / orchestration ─────┐
│ planner.py   拆任务，每步带预期结果            │
│ loop.py      执行一步、截图、验证、路由         │
│ verifier.py  独立判断是否达成                   │
│ router.py    四角色确定性状态机                 │
└───────────────────────────────────────────────┘
                    ↑↓
┌─────────────── 记忆 memory ───────────────────┐
│ trace.py     轨迹落盘                           │
│ skills.py    技能库 RAG（经验）                 │
│ knowledge.py SOP 知识库 RAG（制度）             │
│ recorder.py  人手示范录制                       │
└───────────────────────────────────────────────┘
                    ↓
┌─────────────── 执行 actions ──────────────────┐
│ mouse / keyboard / apps / files / registry    │
└───────────────────────────────────────────────┘
                    ↓
┌─────────────── 安全 safety ───────────────────┐
│ guard.py     风险分级 + 确认门                  │
│ budget.py    步数/时长/调用上限                 │
│ privacy.py   截图脱敏 + 模型路由                │
└───────────────────────────────────────────────┘
```

## 2. 主循环时序

```
用户任务
   │
   ├─ Planner ──▶ 步骤计划（每步含 expected）
   │
   └─ 循环：
        预算检查
          │
        Operator ──▶ 一个工具调用
          │
        确认门（高危才拦）
          │
        执行
          │
        截图 before / after
          │
        Verifier ──▶ continue / retry / replan
          │
        写轨迹
          │
    连续失败 3 次 ──▶ Recoverer ──▶ 重新规划
```

## 3. 两个 RAG 的分工

| | 技能库 | SOP 知识库 |
| --- | --- | --- |
| 存什么 | 以前怎么做成功的（工具序列） | 规定应该怎么做（制度流程） |
| 来源 | 运行轨迹 | 导入的文档 |
| 检索后做什么 | 优先复用，失败回退 | 作为规划依据注入上下文 |
| 指标 | 复用后步数下降率 | 检索命中率、成功率变化 |

两者都用「向量 + 关键词」混合打分：`0.7 * 余弦 + 0.3 * 二字组重叠`。

## 4. 四角色与上下文隔离

| 角色 | 输入 | 输出 |
| --- | --- | --- |
| Planner | 任务、技能、SOP、失败历史 | 步骤计划 |
| Operator | 当前步骤、当前截图 | 一个工具调用 |
| Verifier | 预期结果、执行前后截图 | 判定 + 依据 |
| Recoverer | 最近失败记录 | 新策略 |

**Verifier 的上下文里没有 Operator 的文字解释**——这是代码层面的白名单过滤
（`router.role_context`），不是提示词里一句"请忽略"。

## 5. 三个关键实现决策

### 5.1 坐标归一化

视觉模型返回 0–1000 的归一化坐标，本地按 `round(n/1000 * 宽 * DPI缩放)` 换算成像素。
用 `round` 而非截断，避免逐步累积偏移。

### 5.2 确认门包住执行

```python
guarded_execute(tool, args, confirm_fn)   # 唯一允许的执行入口
```

拒绝时直接返回 `{"blocked": True}`，根本走不到 `execute`。测试用"文件内容未变"来证明。

### 5.3 未知即高危

`classify()` 对未登记工具返回 `destructive`，失败方向偏安全。

## 6. 隐私边界

- 默认只截活动窗口
- 上传前按矩形脱敏
- 原始截图只留本地，不入 git
- 敏感任务切本地模型

当前 `redact` / `route_model` 已实现并有测试，但尚未接入 `capture` 调用链（见 README「当前状态」）。
